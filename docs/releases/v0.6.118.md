# v0.6.118 — QxAI questions and next steps

QxAI can ask structured questions when key information is missing and offer optional next steps as messages users can send with one click.

- `ask_user_question` accepts AskYourQuestion / AskUserQuestion aliases, single or multiple choices, custom answers and skip. Asking ends the current turn and pauses the queue; user input resumes the conversation through the ordinary chat path. Native batches do not execute sibling tools while awaiting an answer.
- `suggest_next_actions` offers up to three next steps with at most one recommendation. Only the latest completed reply has active controls; clicks retain composer drafts, attachments and Skills. QxAI and the reading assistant share the same controls and stale-message guard.
- Thinking steps display concise titles derived from returned content. Search, conversation lists, Workbench titles and section headers share a text axis; model menus and Skills use compact aligned rows.
- Native file pickers retain the host's focus protection until selection, cancellation or failure. Provider/model display names use the configured catalog throughout the conversation UI.

Validation: complete quality gates, TypeScript/Vite production build, MSVC formatting and compilation; runtime question/schema/alias/persistence/pause tests; 24 interaction layout cases plus the reading projection; 64 conversation/Workbench layout cases; existing chat and 120 Shell layout/interaction cases.

Provider and native IPC browser fixtures do not prove live-provider tool selection or installed WebView2 behavior. The installation has not been replaced. Desktop packages are built by the release workflow; a queued or running workflow is pending evidence.

This release consolidates the completed main-branch work after v0.6.117 and was triggered by the repository's cumulative change-volume gate. The first-party plugin catalog remains pinned to `f48ca36142ae1d034b9ba72af4b7544e11d91e5a`.
