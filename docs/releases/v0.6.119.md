# v0.6.119 — Shared image browsing and home panel scrolling

Bing wallpaper and other Workbench media details open in the shared image viewer. Images support 50%–400% zoom, pointer-anchored Cmd/Ctrl+wheel zoom, ordinary wheel scrolling, Shift+wheel horizontal scrolling, overflow dragging and keyboard navigation. Long images open from the top; Esc closes the preview and restores its opener.

The viewer opens immediately and resolves the selected image plus nearby images through the host cache. Slow neighbors do not delay the selected image, and stale requests cannot reopen a closed preview. Controls remain usable in narrow windows and both themes.

Configure Home uses one scroll area across its heading, search, entries and widget controls. Overflow shows the shared thin scrollbar and a faint “Scroll down to see more” hint. The hint disappears at the bottom; reserved bottom space keeps the final item accessible.

This release also includes the completed WebView browser-default policy after v0.6.118: browser find, print, reload, history navigation and whole-window zoom are suppressed while Qx actions, image zoom, text editing and IME retain their own behavior. Auxiliary windows use the same native policy.

Validation covers repository quality gates, TypeScript/Vite production build, Rust formatting and macOS compilation, and production Shell/Workbench browser regression with synthetic media and mock IPC. Browser fixtures do not prove installed desktop behavior or live Bing delivery. The tag workflow builds the macOS Apple Silicon app/DMG and Windows x64 installer; a running workflow remains pending evidence. Local installations are unchanged.

The cumulative change-volume gate triggered this release. The first-party plugin catalog remains pinned to `f48ca36142ae1d034b9ba72af4b7544e11d91e5a`, available on its remote development branch; marketplace packages are unchanged.
