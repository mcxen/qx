## Fixed: windows-ci.yml missing prepare:capture-assets step

**Symptom:** `cargo check --target x86_64-pc-windows-msvc` failed in GitHub Actions
with `resource path binaries\qx-ffmpeg-x86_64-pc-windows-msvc.exe doesn't exist`.

**Root cause:** `windows-ci.yml` runs `cargo check` / `cargo test` directly (not via
`npm run tauri`), so Tauri's `beforeBuildCommand` never executes. The build script
(`tauri_build::build()`) validates `externalBin` + `resources` paths from
`tauri.conf.json`, but `binaries/qx-ffmpeg-*` and `resources/generated/*` are
gitignored and only generated by `npm run prepare:capture-assets`.

**Fix:** Added a "Prepare bundled assets" step (runs `prepare:search-tools` +
`prepare:capture-assets`) in `windows-ci.yml` before `cargo check`.

**Note:** `release-desktop.yml` was unaffected — it builds via
`npm run tauri -- build`, which runs `beforeBuildCommand` (includes
`prepare:capture-assets`) before cargo.

**Key invariant:** Any CI step that invokes `cargo check`/`cargo test`/`cargo build`
directly on `src-tauri` MUST run both prepare scripts first, because the Tauri
build script validates resource/externalBin paths at compile time.

and signed. DMG is not needed for local launch — just use the signed `.app` from
`target/release/bundle/macos/`. To avoid the DMG failure entirely, build with
`npm run tauri build -- --bundles app` (drops dmg/nsis targets).

tauri.conf.json) — process runs in background, summoned via shortcut/dock.

## Fixed: pre-existing Windows compile error in `src/screencap/feedback.rs`

While observing the v0.6.33 CI, the Windows build failed at `cargo check` with
`error[E0369]: binary operation == cannot be applied to type Result<i32, RuntimeError>`
at `src/screencap/feedback.rs:103` (Windows-only `#[cfg(target_os="windows")]` shutter
sound path).

**Root cause:** the code did `crate::runtime::blocking(move || unsafe { PlaySoundW(...) }).await`
and compared the **Result** directly with `0`. `blocking` returns `Result<T, RuntimeError>`
(T = BOOL/i32 from PlaySoundW), so the value must be unwrapped first.

**Fix:** `.map_err(|err| err.to_string())?` then compare the unwrapped `i32` with `0`.
Committed as `a286b2d`, moved the v0.6.33 tag onto it, re-pushed, both Windows CI and
Release Desktop workflows went green.

**Lesson:** Windows-only (`#[cfg(windows)]`) code paths are NOT compiled by the local
macOS `cargo check`, so they only fail in CI. When a Windows CI cargo error appears that
doesn't reproduce locally, grep for `#[cfg(target_os = "windows")]` paths. `rustup` is
not installed locally, so cross-compiling to `x86_64-pc-windows-msvc` for a pre-check
is not available here.

## Fixed: Windows sysinfo plugin failed to load when any system API rejected

**Symptom:** On Windows, the Sysinfo panel refused to render — any single
`context.system.*` rejection (e.g. `Get-NetIPAddress` missing on Server Core,
`Win32_Battery` WMI provider unavailable on a desktop, `Get-NetAdapterStatistics`
cmdlet absent) caused `loadItems()` to `Promise.all` fail-fast, setting
`state.error` and leaving the panel empty.

**Fix — plugin side (`qx-plugins-clone/src/sysinfo/`, bumped to v1.2.3):**
- Synced source up to the already-published 1.2.2 (locale via `context.locale`
  instead of `navigator.language`; `setLocale(context)` in `createPanel` and
  `command.run`).
- Added `settleHardwareItems(ids)` that uses `Promise.allSettled` and drops
  only rejected rows; `loadItems` now routes through it so one failing
  capability (e.g. Network on a NetAdapter-less SKU) no longer blanks System,
  CPU, Memory, Power, or Storage.
- `reload({ selectedOnly: true })` now wraps the single-item fetch in its own
  try/catch and keeps the previous sample on failure, so background polling
  never replaces a good row with an error.
- `AGENTS.md` updated with the failure-tolerance invariant.
- `release-notes.json` + `index.json` + `sysinfo.qx-plugin` repackaged via
  `npm run package:plugins`.

**Fix — host side (`src-tauri/src/system_information.rs`):**
- Added `-ErrorAction SilentlyContinue` to every `Get-CimInstance`
  (`Win32_Processor`, `Win32_OperatingSystem`, `Win32_BIOS`, `Win32_LogicalDisk`)
  and to `Get-NetIPAddress`, `Get-NetAdapterStatistics`, `Get-Process` in the
  Windows PowerShell scripts. A missing WMI provider or absent NetAdapter
  module now returns `$null` / empty array instead of a non-zero exit, so
  the Rust invoke resolves with empty fields rather than rejecting.
- `npm run check` + `cargo check` both green locally; Windows-only paths
  still need the v0.6.34 CI to confirm end-to-end.
